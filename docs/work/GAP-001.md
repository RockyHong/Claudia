# GAP-001 — a changed hook command never reaches an already-installed user

**Logged:** 2026-09-10 · **Source:** propagation check run while building BUG-002's fix
**Problem:** Claudia writes its hook commands into the user's `~/.claude/settings.json`, but nothing re-syncs them when the command text changes in a new version. `mergeHooks` / `writeSettings` run only from `POST /api/hooks/install`, fired by `HookGate.svelte` on first run (when `hasClaudiaHooks()` is false) or by the "Reinstall hooks" button in `ConfigTab.svelte`. `hasClaudiaHooks` only tests for the `127.0.0.1:48901/hook` marker substring — it compares neither content nor version, so a user who installed once keeps the old command text forever. Any fix that lives in the hook command itself therefore ships to new installs only, silently, until someone happens to click "Reinstall hooks". BUG-002's fix is exactly such a change.
**Area:** `packages/server/src/hooks.js` (`hasClaudiaHooks`, `mergeHooks`, `CLAUDIA_HOOKS`), `packages/server/src/routes-api.js` (`POST /api/hooks/install`), `packages/web/src/lib/HookGate.svelte`, `packages/web/src/lib/ConfigTab.svelte`
**Prior:** a content or version comparison in `hasClaudiaHooks` (rather than a marker-substring test) could drive an automatic re-sync, but rewriting a user's settings without asking is a product call — the gate may belong in the UI instead.
