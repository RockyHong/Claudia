# BUG-003 — auto-link resolves a shared window handle, so it can link a session to another session's window

**Logged:** 2026-09-10 · **Source:** measurement taken while grounding BUG-002 (see its 2026-09-10 Amendment)
**Problem:** The auto-link path resolves a terminal window through `Get-Process | MainWindowHandle`, which is a **per-process** property — while a single `WindowsTerminal` process hosts every window and tab on the machine. Measured: a walk started inside the Claudia session's process tree resolved `8391432|QuickCut a747` — a different session's handle and title. Any session auto-linked this way can therefore be pointed at the wrong window, which corrupts click-to-focus (focuses someone else's terminal), the terminal rename (renames someone else's tab), and dead-window pruning (removal keyed on a window the session does not own).
**Area:** `packages/server/src/hooks.js` (`HWND_PREAMBLE` :56-75), `packages/server/src/index.js` (auto-link block), `packages/server/src/focus.js` (window enumeration already used by the spawn path)
**Prior:** the Claudia-spawn path avoids this by enumerating windows and matching on title rather than reading `MainWindowHandle`; the auto-link path may be able to reuse that enumeration instead. Untested.

## Amendment — 2026-09-10 · second failure mode of the same walk

The origin block records the walk resolving the *wrong* window. Measurement taken while verifying BUG-002 found a second, independent failure mode of the same `HWND_PREAMBLE`: it can resolve **nothing at all**, silently.

Run as `bash script.sh` — one extra shell hop over the same command text — the walk returns an empty string on every attempt, while the identical text expanded inline in the calling shell resolves correctly on every attempt. The abort is `if (-not $proc) { break }`: any ancestor pid that cannot be read at that moment (a Git Bash / MSYS intermediate that has already exited and had its pid reaped) ends the walk with no output and no error. `git show HEAD` of the preamble behaves identically, so both failure modes predate BUG-002's build.

Together the two modes say the same thing: ancestry-walk + `MainWindowHandle` is not a dependable way to identify a session's terminal window. Whatever replaces it should be judged on both — right window, and a window at all.
