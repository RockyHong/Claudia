# BUG-002 — terminal-less dispatched sessions land on the board and never leave

**Logged:** 2026-09-10 · **Source:** user observation while running dispatched work
**Problem:** Sessions dispatched without a terminal — producer unconfirmed (Claude Agent SDK, ordinary Agent-tool dispatch, or Workflow) — show up as cards on the sessions board. They then dangle: they never disappear once the dispatched work ends, so the board fills up with dead cards and real sessions get crowded out.
**Area:** `packages/server/src/session-tracker.js`, `lifecycle.js`, `hooks.js`; `docs/specs/sessions.md` § Lifecycle
**Prior:** window pruning is scoped to linked sessions (`windowHandle` non-null), so a terminal-less session's only exit is the 10-minute stale prune — which is apparently not removing them; whether such sessions should be admitted to the board at all is the open half.

## Verdict — surface · 2026-09-10

### Findings

- **admission (half 1) — verified, unconditional.** A registry entry is created for *any* hook POST carrying a string `session_id` (`hook-transform.js:33` is the only payload predicate; `session-tracker.js:122-140` creates on first sight). No terminal-awareness exists anywhere in the trail — nothing keys admission on a resolved HWND, and grep finds no non-terminal session class in server or web. The frontend renders every registry entry (`App.svelte:153` → `SessionList.svelte:23`, no filter, no dismiss control), so registry membership is 1:1 with a board card. Terminal-less sessions are admitted because admission was never a decision — it is the absence of one.
- **removal (half 2) — three exits, all enumerated.** (a) `SessionEnd` → `state:"stopped"` → unconditional delete (`session-tracker.js:114-120`); (b) dead-window prune every 5s, linked sessions only (`index.js:395-414`, filters `s.windowHandle`); (c) stale prune every 60s, **unlinked only** — `windowHandle != null` is skipped (`session-tracker.js:284-296`, guard at :289, timeout `10 * 60 * 1000` at :29). Both entry points reach `tracker.start()` (`bin/cli.js:176`, `bin/standalone.js:11` → `index.js:433`), so "prune never scheduled" is falsified statically.
- **the card's Prior is accurate but incomplete.** It names (b) and (c) correctly; it omits (a), which is the *primary* exit and the one that would fire in under a second. Exit (a) has no filter to fail — a `stopped` event deletes regardless of link state and bypasses the `MAX_SESSIONS` gate (`index.js:192-198`). So the observed dangle requires **both** that `SessionEnd` is never delivered for the producer **and** that exit (c) does not apply.
- **root cause: not isolated within static read — two live traces, one code-verified capability, one unverifiable producer fact.**
  - **T1 — link theft (windowHandle stolen from an ancestor terminal).** Code-verified as *possible*: the `SessionStart` / `UserPromptSubmit` hook runs a PowerShell walk up to 20 process ancestors and returns the first terminal-class process with a non-zero `MainWindowHandle` (`hooks.js:56-75`) — it never checks that the ancestor is the session's own host, so a session spawned from inside a terminal-hosted Claude Code process resolves its *parent's* HWND. `index.js:210-238` links it with no uniqueness check (`:218` tests only `!session.windowHandle`), and `linkSessionById` sets the handle unconditionally (`session-tracker.js:351-354`). Under T1 the phantom is linked → exit (c) skips it, exit (b) sees `IsWindow(hwnd)` true while the parent terminal lives → **the card is unremovable until the parent terminal closes**, which then stops both cards at once. T1 matches the card's "never disappear" literally. Windows-only (`focus.js:262` short-circuits elsewhere). Variant of the same theft: a dispatched session sharing a Claudia-spawned terminal's cwd can consume that terminal's `pendingLinks` entry (`session-tracker.js:130-137`) and take its handle *and* its displayName.
  - **T2 — no link, exit (c) latency only.** If the ancestor walk finds nothing (Claudia-spawned host, non-terminal parent), the phantom stays unlinked and *is* removed — but only 10-11 minutes after its last hook event. Under T2 the premise "never leaves" is false as literally written; the real defect is admission plus a 10-minute residency during dispatch bursts.
  - Discriminator is a single field on a live dangling card; static read cannot reach it. `docs/techstack.md` has no `§ Probes` table, so no probe fires from this door.
- **blast is larger than "board clutter" — two code-verified consequences.** (1) `getAggregateState()` returns `busy` if *any* session is busy (`session-tracker.js:277-282`); a phantom whose `Stop` never arrives pins the whole dashboard — avatar, favicon, document title, SFX, ambience — to `busy`. (2) `MAX_SESSIONS = 100` (`index.js:132`) rejects *new* sessions with HTTP 429 once the registry fills (`:158-164`, `:192-198`) — "real sessions get crowded out" is literal admission denial, not just visual crowding.
- **aim: valid, live, not superseded.** BUG-002 is the only open card (`docs/work/` holds just `README.md`, `TEMPLATE.md`, this card). `docs/decisions.md` carries no row on session admission, pruning, or window linking — no closed fork is re-walked. The two prune behaviors it interacts with were both deliberate (`d8ef9d5` "skip linked sessions during stale pruning"; `c893026` "prune dead sessions for all linked windows") — a fix must not simply revert either, since each closed its own stale-card bug.
- **scope reach (all files native to this repo; nothing vendored or served from another repo, so no upstream contribution route applies):** `packages/server/src/index.js` (admission cap :132 / :158-164 / :192-198, auto-link :210-238, dead-window prune :395-414) · `packages/server/src/session-tracker.js` (create :31-47 / :122-140, stopped-delete :114-120, `pruneStale` :284-296, `hwndTaken` guard :342-347, `linkSessionById` :351-376, aggregate :277-282) · `packages/server/src/hooks.js` (`HWND_PREAMBLE` :56-75, `CLAUDIA_HOOKS` :81-108) · `packages/server/src/hook-transform.js:33` · tests `session-tracker.test.js` (`stale session pruning` :447-533 already codifies the skip-linked rule at :511), `index.test.js`, `hooks.test.js` · `packages/web/src/App.svelte` + `lib/SessionList.svelte` only if the class must render distinctly (server-side filtering is preferred — `docs/techstack.md` § Data flow is unidirectional).
- **doc impact if a fix lands:** `docs/specs/sessions.md` § Lifecycle (:47-54, both prune bullets) and § Window linking (:36-41, the auto-link contract) · `docs/specs/dashboard.md:67` ("Orphan session fallback" known issue, same surface) · `docs/specs/hooks.md` :17-27 only if a hook type or its state mapping changes · `docs/overview.md` § Features only if the board's admitted population changes user-visibly.
- **attempted:** full trail read (tracker, index, hooks, hook-transform, transcript-scan, focus, both bin entry points, frontend session path, both specs, overview, dashboard spec, decisions, work index, git history of the two prune commits). Stopped at the T1 / T2 fork: separating them needs one observation of a live dangling card, which no static read supplies and no probes table authorizes this door to take.

### Decision needed

Two decisions, ordered — the measurement gates nothing in the first, so the product half can be ruled now and the mechanism half confirmed before code lands.

**1. Admission policy — what population does the board represent?** (the card's half 1)

- **A — terminals only.** Refuse registry admission to any session with no resolvable terminal window of its own. Board population = "things you can click to focus", matching the product frame in `docs/overview.md` § Problem / Solution ("which terminal?", one-click focus) and the naming contract in `docs/specs/sessions.md` § Naming. Cost: dispatched work becomes invisible — including its contribution to `busy`.
- **B — admit, and give terminal-less sessions a working exit.** Keep them as cards; make exit (c) actually reach them (see decision 2) and consider a shorter timeout for the unlinked class. Cost: cards that do nothing on click (`POST /focus/:sessionId` falls back to fragile title matching — already a known issue at `docs/specs/dashboard.md:67`).
- **C — admit as a distinct non-focusable class** with its own lifetime rule (rendered differently, excluded from focus and possibly from aggregate state). Cost: a new session class across server + frontend + spec; the largest surface of the three.
- **recommendation: A**, with the aggregate-state consequence stated: the product SSOT frames every card as a terminal to jump to, and a dispatched session's activity is already visible on its *host* session's card (it is the host that stays busy). B keeps a card whose primary interaction is broken by construction.
- **settles by:** user judgment — product call on what the board is for. `docs/overview.md` § Problem / Solution and `docs/specs/dashboard.md` § Focus on Click both lean A but neither ratifies an admission rule, and no `docs/decisions.md` row covers it.

**2. Root-cause confirmation before any fix lands — is the dangling card linked or unlinked?**

- **T1 (linked / HWND stolen from an ancestor)** → the dangle is permanent, and the fix must include an HWND-uniqueness guard on the auto-link path whichever admission option wins; option B without it does nothing, since exit (c) stays skipped.
- **T2 (unlinked)** → the dangle is a 10-minute residency, exit (c) works as designed, and the fix is admission policy plus possibly a shorter unlinked timeout.
- **recommendation:** take the measurement before scoping; then land the HWND-uniqueness guard on `linkSessionById` in either case — the codebase already treats "this HWND is taken" as a reason not to assign it on the sibling path (`session-tracker.js:342-347`, added by `6341e11`), and a shared HWND independently corrupts terminal rename (`index.js:229-231` renames the *parent's* tab to the phantom's name), click-to-focus, and dead-window prune fan-out. Applying an already-codified invariant to the path that lacks it is `systematic`, not a design call.
- **settles by:** `inline read` — with a dangling card on the board, `GET http://127.0.0.1:48901/api/sessions` (read-only; shape is `docs/specs/sessions.md` § SSE Contract). Read the dead entry's `windowHandle` and `lastEvent`: a non-null handle — especially one duplicated across two entries — is T1; a null handle with `lastEvent` older than 11 minutes is T2 and reopens "why did exit (c) not fire".

## Design — 2026-09-10

Ruling on the verdict's decision 1: **option A — terminals only**. Decision 2's measurement was taken before this block landed and returned **T1, reproduced live**: a headless `claude -p` run launched from inside this session's process tree was admitted as its own card and assigned HWND `199972` — the *same* handle already held by the parent session's card. The parent process exited; the phantom card was still present 60s later in state `idle`. Both dangle conditions confirmed together: `SessionEnd` did not remove it, and being linked it is skipped by `pruneStale` (`session-tracker.js:289`), so it survives as long as the parent terminal lives. Added fact from the same pass: the server exposes no session-delete route (`routes-api.js` has `DELETE` for projects and avatars only), so a dangling card has no manual dismissal path.

Three changes, one logical unit — the guard is a prerequisite for the admission predicate, since a stolen handle makes a phantom look like it owns a terminal.

**1. HWND-uniqueness guard on the auto-link path.** `linkSessionById` (`session-tracker.js:351-376`) refuses an HWND already held by another live session, applying the invariant the sibling path already codifies as `hwndTaken` (`:342-347`, from `6341e11`). The refusal is signalled in the return value so `index.js:229-231` does not rename the holder's terminal tab to the refused session's name.

**2. Terminal-only admission, Windows only.** A registry entry is created only when the session presents a terminal of its own:
- creation is allowed from a header-bearing hook (`SessionStart` / `UserPromptSubmit`) whose `X-Hook-Window` HWND parses `> 0` and is not already held by another live session, or from a matching `pendingLinks` entry (Claudia-spawned terminal, whose handle arrives later via the title poll);
- every other hook type updates an existing session only — it never creates one, which is also what makes a refusal stick without a deny-list: the refused id simply never appears, and its later `PreToolUse` / `Stop` events find nothing to create;
- `POST /event` (the legacy JSON endpoint, no header) keeps its current behavior — the Claudia hooks all post to `/hook/:type`.

**3. Platform gate — the predicate binds only when the server runs on `win32`.** HWND resolution is a Windows capability: the hook preamble shells to `powershell` (`hooks.js:56-75`) and yields an empty header everywhere else, and `focus.js:262` already short-circuits off-Windows. CI builds and ships Linux, Windows and macOS (`docs/techstack.md` § CI), so an ungated predicate would empty the board on two of the three platforms. Off-Windows, admission stays unconditional as today.

**Accepted cost, recorded rather than mitigated.** On Windows, a session whose ancestor walk resolves nothing — a terminal host outside `HWND_PREAMBLE`'s `$names` list, e.g. an IDE-integrated terminal — is no longer admitted at all, where today it appears as an unlinked card. That is option A's definition applied consistently (no resolvable terminal of its own → not a board card), not a regression to fix separately. Refusals log a one-line `[admission] refused` reason so a missing card is diagnosable from the server console.

**Test surface** — `session-tracker.test.js` (guard: taken HWND refused, holder keeps its handle and name; admission: non-header hook does not create, header hook with a free HWND does, `pendingLinks` path still creates) and `index.test.js` for the route-level wiring including the `win32` gate. `pruneStale`'s existing skip-linked assertion (`:511`) must stay green — the fix removes the phantom's *linkage*, it does not relax that rule.

## Amendment — 2026-09-10 · gateway integration check

The first `## Design` block's central premise is **falsified by measurement**. It assumed an HWND already held by another session implies the claimant is not its own terminal's host. It does not, on this machine or any like it.

Running `HWND_PREAMBLE` (`hooks.js:56-75`) with a per-hop trace, from inside this session's own process tree:

```
hop 0 powershell → hop 1..3 bash → hop 4 claude (pid 30912) → hop 5 cmd → hop 6 WindowsTerminal (pid 12008)
RESOLVED: 8391432|QuickCut a747
```

Two facts, both load-bearing:

1. **`MainWindowHandle` is a per-process property, and one `WindowsTerminal` process hosts every window and tab.** The walk started in the *Claudia* session's tree and resolved the *QuickCut* session's handle and title — the WT process's main window, not this session's. A machine-wide enumeration confirms a single `WindowsTerminal` process (pid 12008, handle 8391432). So every auto-linked session hosted by that process presents the *same* handle. Handle collision is the normal case here, not theft.
2. Therefore the built predicate inverts in production: the first session to claim `8391432` is admitted and **every other genuine interactive session is refused as a thief** — the board would hold one card. The card `Claudia db45` escaped only because it was linked through the Claudia-spawn title-poll path (`199972`), never through this header.

The same measurement kills change 1 as well: `linkSessionById`'s uniqueness guard has no valid premise on the auto-link path, since sharing a handle is legitimate. The verdict's `systematic` framing (applying `hwndTaken` from `session-tracker.js:342-347`) holds only for the *spawn* path, where each spawn is a distinct new window.

The same trace supplies the correct discriminator: hop 4 is a `claude` process sitting between the hook and the terminal. A top-level session's walk reaches the terminal with exactly one `claude` in the chain — its own; a nested or dispatched session's walk crosses **two or more**. Nesting is what the card's premise actually describes, and it is directly readable.

## Design — 2026-09-10 (supersedes the first Design block)

Ruled by the user after the measurement above: **admission keys on nesting, not on handle collision.** Option A's product frame (board = terminals you can click to focus) stands; only the predicate changes.

1. **Revert change 1.** `linkSessionById` keeps assigning the handle it is given — no uniqueness guard, no `{refused:true}` path, and `index.js` keeps its rename call. Shared handles are legitimate. `storeWindowHandle`'s own `hwndTaken` check (`:342-347`) stays as it is — the spawn path's premise is unaffected.
2. **Preamble reports nesting.** `HWND_PREAMBLE` counts `claude` processes crossed before it reaches the first terminal-class ancestor and reports the result in its own header (`X-Hook-Nested`), leaving `X-Hook-Window`'s `hwnd|title` shape untouched. Two or more ⇒ nested.
3. **Admission predicate, Windows only.** A session is created only when it is **not nested** *and* presents a terminal — a parsed HWND `> 0` (shared or not; the free-handle test is gone) or a matching `pendingLinks` entry. Non-header hook types still never create, which is what makes a refusal stick without a deny-list. Off-Windows, admission stays unconditional.

The `allowCreate` plumbing, the platform gate (`isWindowsHost`), the `hasPendingLink` helper and the refusal logging all survive from the first build; the predicate's body and change 1 are what get rewritten.

**Propagation** — the preamble text lives in the hook commands Claudia writes into the user's settings, so the change only reaches an installed user when Claudia re-syncs its hooks. The build confirms that path fires rather than assuming it.

**Verification owed before commit:** a live end-to-end run — a headless `claude -p` launched from inside a session must produce no board card, while the launching session's own card stays intact.

## Amendment — 2026-09-10 · pre-commit live verification

Verifying the second Design's change 2 against the real process tree turned up a **pre-existing defect in the preamble itself**, and it forces one adjustment to change 3.

Measured three ways, each repeated three times, deterministic:

| invocation | result |
|---|---|
| payload passed straight to `powershell` as one argument | `11406204\|super-bootstrap 497d@@1` |
| the generated joined one-liner, expanded inline in the calling shell | same, stable |
| the same generated one-liner run as `bash script.sh` (one extra shell hop) | **empty** |

`git show HEAD` of the preamble fails identically, so this is not introduced by this card's build. The walk aborts at `if (-not $proc) { break }`: when any pid in the ancestor chain cannot be read at that moment — a Git Bash / MSYS intermediate that has already exited, its pid reaped — the loop breaks and the whole command returns an empty string silently. Which shape the hook's shell takes therefore decides whether `X-Hook-Window` carries anything at all.

**Adjustment to change 3, forced by that measurement.** The predicate as built is `!nested && hasTerminal`, so an empty header refuses admission. With a walk that can silently return nothing for reasons unrelated to nesting, that inverts into the exact regression this card must not ship: real interactive sessions vanishing from the board. The predicate becomes **`allowCreate = !nested`** — refusal requires *positive* evidence of nesting (`X-Hook-Nested >= 2`); the `hasTerminal` half is dropped.

This softens option A's literal reading — a session whose terminal never resolves still gets a card — and it is chosen deliberately for its failure mode. Failing open, a phantom whose walk breaks is admitted *unlinked*, which puts it back under `pruneStale` and bounds it at ~10 minutes (the T2 shape) instead of the permanent dangle this card was filed for. Failing closed, one broken walk erases a real session from the board with no diagnostic. The nesting signal keeps working for every phantom whose walk completes — which is the case actually measured on this machine, where the walk resolved and counted correctly.

Second failure mode of the same walk (wrong handle rather than no handle) is logged separately as BUG-003.
